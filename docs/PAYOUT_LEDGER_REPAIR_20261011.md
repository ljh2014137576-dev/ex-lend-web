# 工资结算与流水修复（2026-10-11）

本轮修复已有工资、凭证及流水功能，没有新增业务模块。财务页原来每天使用相同批次号，工资页每次重试又生成新号；工资记账和附件上传共用失败分支，可能把已成功记账误报为失败。员工/客户流水则存在按姓名关联、单页截断及未知字段补零的问题。

## 工资与附件

- 财务页工资入口统一进入工资结算页，只有一个资金提交流程。
- 请求在首次提交前固定并持久保存，按项目/账号隔离，以 Web Locks 协调同浏览器标签页；旧草稿不能越过新请求。必要锁/存储不可用或记录损坏时不降级提交。
- 后端 PB2 请求标识绑定操作人及规范化员工/分金额集合；完整回执、批头、明细、工资流水同事务提交。同标识同内容返回原回执，异内容拒绝，不通过新批号绕过未知结果。
- 没收到响应时核对或使用原标识重试；暂未查到回执不能证明之前请求不会成功。成功后从服务器读取余额，不在缓存上重复减款。
- 记账后凭证上传/绑定单独处理，可从成功回执或结算记录补传；附件处理没有工资 RPC 依赖。上传结果未知保留原文件路径及上传标识，不自动删除文件。
- 凭证关联验证真实对象、上传账号、目标批次，并比较开始上传时看到的旧路径；相同路径重放安全，过期请求不能覆盖另一操作的新凭证。冲突时保留现有凭证并要求核对，不自动放弃旧附件意图或覆盖新文件。
- 旧页面无 PB2 标识的资金请求会明确要求刷新，且零写入；已有历史批次缺明细时只读/补附件，不冒认为可重放的新回执。

入口：`finance/page.tsx` → `payroll/page.tsx` → `PayoutSettlementDialog` → `payout-request.ts` → `payout_salary` / `get_payout_receipt`。附件为 `PayoutProofEditor` → `payout-proof.ts` → `attach_payout_proof`。

## 流水

- 工资、客户和员工数据关联使用真实 UUID；没有关联字段时明确未知，不根据同名、单号、日期或金额猜测。
- 按原始时间与 ID 稳定游标读取到空页，服务器返回短页不是结束；任一页失败、重复/不前进、非法游标均不返回假全量。
- 保留类型、金额符号、原始时间、操作人、备注、订单/批次及凭证；未知金额/余额显示未知。佣金净额包含 `commission` 与 `refund_deduct`，避免撤销后重审重复累计；其他变动保留正负。
- 弹窗区分加载、失败、真实空列表；汇总标明只基于已保存流水，历史缺失不等于从未发生业务。
- 已审核订单的成员提成快照可单独显示为核对参考；它不是钱包流水，订单日期不是入账时间，缺失历史余额也不会推算。这些参考不参与钱包余额或流水累计。

入口：`lib/ledger-pagination.ts`、`ledger-types.ts`、`ledger.ts`、`supabase-api.ts`；员工/客户/财务/工资页面，以及 `OrderPreview`、`LedgerPartners`。
