# 客户创建、充值与员工手机号写入修复

本次只修改 `app/(shell)/customers/page.tsx`、`app/(shell)/employees/page.tsx`，以及后续明确纳入的 `app/(shell)/settings/page.tsx` 头像结果判断。未修改公共 API、登录/密码流程或 SQL。提交、日志、索引与发布由主流程整合。

## 客户创建

- 真实会话使用 `customer.insert(...).select(...).single()`，必须拿到有效 UUID 和完整余额投影后才把客户加入缓存；真实路径不再展示 `c + Date.now()` 临时客户。
- 创建失败保留姓名、电话、类型和对话框，不写假客户缓存。没有明确确认的结果要求先刷新核对，避免重复创建。
- `useRef` 在第一个 await 前同步上锁，配合提交按钮/输入框禁用，防同一事件周期重复提交。
- 本地模拟写入仅限 `NEXT_PUBLIC_ENABLE_MOCK_LOGIN=1` 且已有 mockRole；真实会话读取失败不会转成模拟成功。

## 充值

- 真实路径再次检查客户 UUID；RPC 保留原有五参数合同：客户 ID、本金、赠送、备注、凭证路径。
- 仅 `success === true` 代表充值确认成功。RPC 错误、`success:false`、网络异常均不提前增加本地余额，不创建虚构流水。
- 成功后并行读取该客户的真实余额及服务器流水；不根据旧缓存自行相加，也不以 `Date.now()` 生成真实流水 ID。
- 已确认成功但刷新失败时，明确提示“充值已成功、刷新未完成”，关闭确认框并禁止再次充值，要求刷新页面核对。未知网络结果同样阻止直接重试。
- RPC 明确拒绝时保留金额表单和对话框，允许修改后再提交。缺失余额展示为“—”，空金额不会被转换为 0；不完整服务器余额不会被伪造成 0 后入缓存。

## 员工与头像

- 员工 INSERT 增加 `phone: form.phone.trim() || null`，保持输入字符串和前导零；留空写 NULL，不把占位文字当手机号。员工现有其他创建交互未重构。
- 头像上传后的 `update_self_avatar` 也必须明确返回 `success:true`。失败/无确认时不申请新显示 URL、不更新头像缓存、不发送 `avatar-updated` 成功事件，并显示错误。
- 数据库侧 `employee INSERT(phone)` 授权由权限流程独立补充；本次代码不会绕过权限。

## 验证

- `node node_modules/typescript/bin/tsc --noEmit --incremental false` 通过。
- 直接从三份 TSX 的 TypeScript AST 提取实际处理函数，在内存转译执行，使用模拟网络、React setter 和同 tick 重入；没有访问浏览器或真实数据库。15 项行为检查全部通过：
  1. 创建等待服务器 UUID，且同 tick 双调用只有一次 INSERT。
  2. 新客户紧接充值使用服务器 UUID 和准确五参数；真实流水覆盖测试占位数据。
  3. 创建拒绝保留表单与缓存。
  4. 非 UUID 的创建结果不能进入缓存或继续收费。
  5. 缺失服务器余额不能被补 0。
  6. 无会话、mock 关闭时不走本地假写入。
  7. RPC `success:false` 不增加余额、不改流水，保留充值表单。
  8. 网络拒绝不改余额，标记需要核对并阻止重放。
  9. 同 tick 双充值只有一次 RPC，余额以服务器刷新结果为准。
  10. 充值已确认但刷新失败时关闭表单、明确成功状态、阻止重复充值。
  11. 空赠送金额被拒绝，不变成 0。
  12. 员工手机号使用提交时闭包中的原字符串，保留前导零。
  13. 空员工手机号写 NULL。
  14. 头像 RPC 失败不更新缓存或发送成功事件。
  15. 头像没有明确 success 时不假报成功。

这些是实际处理函数的针对性测试，不等于最终浏览器视觉验收；独立代码审查和整站构建由主流程继续完成。
