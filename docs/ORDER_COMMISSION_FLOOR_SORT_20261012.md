# 工资订单排序与订单类型提成下限（2026-10-12）

工资结算页的员工订单弹窗原来对本地格式日期做字符串排序，跨月或日期未补零时顺序错误。现在优先用 `createdAtRaw` 的真实时间戳降序排列，最新在前；兼容旧缓存和演示日期，无效时间放最后，同时间按 ID 稳定排序。只对该员工筛选出的新数组排序，不改变员工钱包余额排序或共享订单数据。

新增商品原来将固定比例写死为 8%，新增等级默认 12%。本轮把新增与编辑提成配置的有效范围统一为 80%–100%，表单用明确百分数，默认 80%；比例不合法时先提示，不发送请求或写入缓存。真实保存成功后再更新显示，失败保留草稿。输入最多两位百分数小数，与数据库 `numeric(6,4)` 对齐；通过十进制字符串移位避免 80.1/100 的浮点差异被误判成保存失败。

## 服务端约束

- 产品新增或改变提成配置时，固定比例必须为有限且非空的 0.8–1；等级规则新增或改变时同样约束。
- 原有低比例商品不自动调高或删除，仍能下架/隐藏；列定向触发器避免对旧行的无关更新一概报错。旧订单、提成、余额和流水不批量重算。
- `create_order_multi` 与 `edit_order` 在资金写入/旧支付冲正前调用私有校验，使用真实商品及所选员工的等级规则；客户端传入伪造比例不作为依据。持有客户、员工、产品及适用规则锁直到快照写入结束，防止校验与快照来自不同配置。
- 新增或改变商品快照时再次验证固定比例下限，避免经改选商品绕过。正常 0/1/2 名员工流程保留；按等级但尚未分配员工的预约仍可创建，选人后校验实际规则。
- 下限指商品/等级的适用提成比例，**不是每位员工金额占整张订单的比例**。例如 100 元订单由两人分配基数、适用 80% 时，每人 40 元合法。
- 本轮边界是订单类型配置、新建和改选商品。完成后的独立人工佣金调整流程、原审核 RPC 和历史缺失保护不变，不借本次操作重写已存在账目。
