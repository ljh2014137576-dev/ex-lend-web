# 单账号登录与管理岗权限核验（2026-10-16）

本次检查发现目标邮箱在当前 Auth 用户和登录身份中不存在，后台用户也没有对应记录；已检查的历史备份未找到可恢复的原身份。用户确认角色为管理岗后，按当前身份重新补建登录和业务权限，没有猜测原账号 ID 或绑定其它用户的历史记录。

## 安全处理

- 官方 CLI 授权失效时由用户完成官方登录，不索取访问令牌。管理密钥通过子进程匿名管道留在内存，不输出或保存。
- 图片密码的本地识别结果不一致，未尝试猜测或向认证端点试多个密码。改由用户在本机 `Read-Host -AsSecureString` 隐藏输入两遍，并在内存确认。
- 管理密钥可用性与格式检查放在密码提示之前。Windows PowerShell 5 的 `@($json | ConvertFrom-Json)` 会给根数组额外包装一层；先赋值解析结果再显式枚举行，兼容其实际行为。此处曾导致一次创建前失败，确认没有 Auth 写入后才允许重新运行。
- 官方 Auth Admin 创建后，使用同一内存密码与公开客户端 key 进行真实密码登录，并核对新用户 ID。随后只退出本次测试会话，不注销其它人的会话。
- 业务用户必须与已确认 Auth ID、邮箱和 email identity 一一对应；只新增 manager/active 资料，不覆盖已有用户。旧结构要求的密码哈希在数据库内部复制，不返回到客户端或工件。

## 结果与边界

密码登录接口返回 200；管理岗资料已补齐。以 authenticated 身份及该用户 ID 核对：`is_staff()` 为真、`is_boss()` 为假，订单读取允许，密码哈希列读取不允许。Auth 用户、email identity、业务资料各新增一条，其余业务用户的身份与权限摘要相同；测试会话数量为零。

本次未修改前端、公共业务函数、数据库权限策略或账目。服务端密码验证与行权限验证已完成，不冒称执行了真实浏览器逐按钮验收。账号创建/登录工具只在仓库外私有恢复目录使用；仓库中不保存邮箱、密码、密钥、会话或哈希值。

本机私有证据目录：`restore-plan/account-login-20261016/`。其中 `manual-result.json` 仅含白名单状态、用户 ID 与验证布尔值；另有安全前置状态、离线检查、密钥结构检查以及后置权限核对。发生未知网络结果时先核对服务端，不自动重试创建、改密或删除用户。
